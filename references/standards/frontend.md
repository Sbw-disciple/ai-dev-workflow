# 前端规范

不绑定 React、Vue、Angular 或任何具体框架。先读项目配置确定实际方案，以下约束结果和边界，不规定语法。

## 1. 先定包管理器

按锁文件来，不猜：

| 锁文件 | 用 |
|---|---|
| `pnpm-lock.yaml` | pnpm |
| `yarn.lock` | Yarn |
| `package-lock.json` / `npm-shrinkwrap.json` | npm |
| `bun.lock` / `bun.lockb` | Bun |

多份锁文件并存时先看文档和 CI；仍不明确就问。不自动安装、升级、切换包管理器。

## 2. 目录职责

存量项目沿用现有结构。新项目或新边界才参考下面这套职责划分，不要机械建满目录：

```text
src/
├── app/         入口、全局 Provider、启动配置
├── pages/       路由页面或页面级组合
├── features/    按业务能力聚合的组件、状态、用例
├── components/  真正跨业务的展示组件
├── api/         HTTP 客户端、端点适配、传输类型
├── stores/      确有跨功能共享需求的客户端状态
├── router/      路由声明与守卫
├── styles/      令牌、基础样式、主题
├── types/       少量跨模块共享类型
├── assets/
└── tests/       项目约定集中存放的测试
```

依赖方向：页面 → feature → 共享 UI / 基础设施。共享模块不许反向依赖页面或 feature。业务专属代码优先放进对应 feature，不往上提成全局。

## 3. 组件职责

- 页面管路由级组合，不直接承载大量请求、缓存、权限和复杂业务规则。
- 拆组件的依据是「有几个变化原因」，不是行数。
- 展示组件靠明确的输入和事件工作，不偷偷读无关全局状态。
- 业务逻辑抽成可测的函数、hook、composable 或 feature 层代码。
- 已有设计系统、基础组件、领域逻辑不重写。
- 不擅自改布局、文案、交互流程、视觉风格。需求确实涉及体验变化时保持整体一致并说明影响。

## 4. 类型与接口

- TypeScript 项目不用 `any`、双重断言、全局关检查来绕错误。未知输入先 `unknown` 再验证收窄。
- Props、事件、路由参数、表单模型、状态、API 边界都要有明确类型。
- 传输 DTO 与视图模型语义不同时显式映射，别让后端字段结构渗透整个 UI。
- 生成的 API 类型通过 schema/OpenAPI 流程产出，不手改生成文件。
- 区分「缺失」「null」「空字符串」「空集合」「0」，不用真值判断掩盖有效数据。

## 5. 请求与状态

- HTTP 客户端、鉴权头、序列化、错误映射集中处理，页面不重复拼底层请求。
- 每个异步界面把实际会出现的状态处理掉：初始、加载、成功、空、失败、取消、重试。
- 防竞态：组件卸载或查询条件变化时，按框架能力取消或忽略旧响应，别让旧结果覆盖新结果。
- 服务端状态交给项目已有的数据请求/缓存方案，不无理由复制进全局 store。
- 客户端状态只提升到够用为止，不要一个巨型 store。
- 乐观更新必须有失败回滚和最终一致性策略。

## 6. 表单与输入

- 前端校验只管即时反馈，后端必须独立再校验一次。
- 写清必填、长度、格式、边界、依赖字段、重复提交行为。
- 提交中防重复点击，但不要把界面永久锁死。
- 错误定位到具体字段或操作，保留用户能安全重试的输入。
- 上传校验类型、大小、数量。只信扩展名或浏览器 MIME 等于没校验。

## 7. 样式、响应式与可访问性

- 沿用现有 CSS 方案、设计令牌、组件库，不同时引入第二套样式体系。
- 样式限定作用域，避免无意覆盖全局元素或第三方组件。
- 关键页面至少检查窄屏、常规桌面、长文本、空数据、错误态，不针对单一尺寸硬编码。
- 用语义化元素；交互控件能键盘操作且有可访问名称。
- 图片给替代文本，装饰图不要制造噪声。
- 焦点可见，弹窗和路由切换正确管理焦点。颜色不作为传达状态的唯一手段。

## 8. 安全

- 不把未处理的外部 HTML 注入 DOM；确需富文本时用项目认可的白名单清理方案。
- 前端不存服务端秘密。令牌存储、Cookie 属性、CSRF 策略服从后端认证设计。
- UI 权限只管体验，服务端必须再授权一次。
- 外部 URL、重定向、下载名、资源地址要校验协议和目标，挡住开放重定向和 `javascript:`。
- 错误提示、埋点、控制台不泄露令牌、个人数据、完整请求体、内部堆栈。
- 用框架自带的转义，不用字符串拼 HTML、脚本、查询表达式。

## 9. 性能

- 优化要有依据：测量数据或明显的复杂度问题。没有证据不memo、不缓存、不虚拟化。
- 避免无界列表、重复请求、重复订阅、未释放监听器、渲染期做重计算。
- 路由级或确实大的功能可延迟加载，不要把微小模块拆碎。
- 图片和媒体按实际显示尺寸优化，别阻塞首屏。
- 缓存必须有失效策略，不能拿陈旧数据换表面性能。

## 10. 测试

- 测用户能观察到的行为和关键业务状态，不锁框架内部实现和脆弱 DOM 结构。
- 纯业务函数做单测；组件覆盖关键交互、加载、空、失败、权限态；关键流程按项目能力做集成或端到端。
- 修缺陷要加一条「修之前红、修之后绿」的回归测试，除非技术上做不到并说明原因。
- Mock 只隔离真正的外部边界，不要把被测逻辑自己 mock 掉。
- 用稳定的可访问查询，不依赖随机时间、真实网络、共享全局状态。

## 11. 验证顺序

格式检查 → Lint → 类型检查 → 相关测试 → 更大范围测试 → 构建。只跑项目已有且已授权的命令。没有统一命令时可用 `scripts/verify-frontend.ps1`。

## 12. 收工前照着挑

巨型组件、重复的 API 封装、滥用 `any`、副作用依赖不全、竞态、缺错误态或空态、样式泄漏、只能鼠标操作、监听器未清理、敏感数据进日志、前端代替后端鉴权、无依据的全局状态、无关的 UI 改版。
