# 共享规范

适用于任何真实代码任务。前后端细则见同目录 `frontend.md`、`backend-agent.md`、`mobile.md`。

## 1. 冲突时的优先级

从上往下取，前一条压住后一条：

1. 用户本次的明确要求，以及他划定的授权边界
2. 安全：数据、权限、依赖、秘密、不可逆操作
3. 正确：需求语义、接口契约、边界条件、并发与持久化一致性
4. 可读：命名、职责划分、控制流、必要说明
5. 项目里更具体的既有约定
6. 性能、复用、抽象层次的个人偏好

安全或正确性和现有代码冲突时，不要顺着现状写。给出证据、说明风险、给最小修复方案；修复会超出本次范围，就先问。

## 2. 动手前必须读出来的事实

只写从文件里能确认的东西，不靠目录名推测行为。

| 类别 | 看什么 |
|---|---|
| 规则 | `AGENTS.md`、贡献指南、开发文档、架构决策记录 |
| 前端 | `package.json`、锁文件、tsconfig、构建与路由配置、状态管理、样式方案、测试配置 |
| 后端 | 构建文件、框架版本、数据访问、迁移、接口文档、认证、日志、部署配置 |
| 自动化 | CI 工作流、Git hook、格式化器、Lint、类型检查、安全扫描 |
| 上下文 | 调用方与被调用方、公开类型、数据库约束、已有测试 |

技术栈确实判断不出来、且不同选择会显著改变结果时，才去问。

## 3. 变更范围

- 存量项目只做最小完整变更。不做顺手清理，不做整文件格式化。
- 新项目用该技术栈的常规结构，但脚手架、框架、依赖的选择先确认。
- 拆文件的依据是职责边界，不是行数。
- 禁止循环依赖、跨层访问、底层反向依赖 UI 或具体供应商。
- 生成物、锁文件、数据库迁移只通过项目认可的工具改，不手编。

## 4. 依赖与配置

- 先用标准库和已有依赖。真要新增，比较维护状态、许可证、体积、安全记录，然后确认。
- 配置按环境注入，仓库里只放无秘密的示例；启动时校验必需项，报错要能照着改。
- 开发环境的默认值不等于生产安全值。
- 不绕过证书校验、鉴权中间件、权限检查、依赖锁定。

## 5. 错误处理

- 在边界把底层错误翻译成稳定的领域错误或接口错误，同时保留能定位的根因链。
- 不捕获后忽略，不返回虚假成功，不把堆栈、SQL、密钥、内部路径丢给用户。
- 超时、取消、重试、资源释放要能区分。只有幂等或明确安全的操作才自动重试。
- 错误信息说清「发生了什么」和「下一步怎么做」，不泄露内部细节。

## 6. 数据与编码

- 跟着 `.editorconfig`、`.gitattributes`、格式化配置走；没有规定的文本文件用 UTF-8。
- 跨系统的字符集、时间、时区、数字、金额、枚举、空值语义必须写明。
- 接口用标准 JSON 和明确的 `Content-Type`，不要拿平台默认编码处理网络或持久化数据。
- 金额用定点小数或最小货币单位，不用二进制浮点表达业务金额。
- 时间存储与传输用 UTC 或明确时区，只在展示层转本地。

## 7. 注释与文档

- 标识符用清晰英文，不用拼音、不用模糊缩写、不在名字里重复类型。
- 中文注释解释「为什么这样」「约束是什么」「为什么不采用直觉方案」，不逐行翻译代码。
- 公共接口、复杂算法、兼容性行为、安全边界，要有和项目风格一致的文档。
- 行为改了，同步改文档和示例。不留已经失真的注释。

## 8. 需要用户决策时怎么问

一次把五件事说全，别挤牙膏：

1. 现在的事实和证据
2. 不处理会怎样
3. 至少一个可行方案及主要取舍
4. 明确标注推荐哪个、为什么
5. 等确认期间还能安全做什么

## 9. 八条红线

下面这些动作不因为「已经允许动手」就自动放行，必须先说影响再执行：

| # | 红线 |
|---|---|
| 1 | 新增、升级、替换第三方依赖 |
| 2 | 改公共 API、持久化格式、数据库结构或已发布的迁移 |
| 3 | 破坏向后兼容 |
| 4 | 大规模移动/重命名文件、跨模块重构、删除可能仍在用的旧代码 |
| 5 | 改构建、部署、格式化、Lint、类型检查、测试、安全策略配置 |
| 6 | 现有约定与安全或正确性冲突，而修复会扩大范围 |
| 7 | 存在多个合理方案且会明显改变架构或用户体验 |
| 8 | 关键验证跑不起来，却要以未验证状态交付 |

## 10. 工作记录

每个真实任务维护两样东西，位置统一在项目的 `.ai/`：

| 文件 | 什么时候写 | 内容 |
|---|---|---|
| `.ai/operations.md` | 每次有意义的改动后追加 | 时间、操作、目标、原因、结果、恢复方式 |
| `.ai/reports/<时间戳>-<任务>.md` | 任务结束时写一份 | 见 `references/report-template.md` |

时间统一 `yyyy-MM-dd HH:mm:ss +08:00` 格式。不写令牌、密码、个人数据、完整环境变量、敏感业务内容。

项目已有记录位置时，用项目的位置，不要另起一套。
