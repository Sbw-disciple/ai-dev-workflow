# 来源与改造说明

这套东西由两条独立的来源合成：一条提供**过程**，一条提供**标准**。两者没有重叠，合起来才覆盖一次开发的全部环节。

## 来源一：过程骨架

来自一位抖音开发者（用户 414094）分享的个人实践《我的 AI 日常开发工作流》，原文以三页图文记录了九个步骤，配套一组自定义命令（`/grill-me`、`/to-spec`、`/to-tickets`、`/tdd`、`/code-review`）。

本仓库把与具体工具绑定的部分剥离，保留流程骨架，改成任何能读写文件的 AI 环境都能执行的七个阶段。

### 原始九步

| # | 步骤 | 原始做法 |
|---|---|---|
| 1 | 开对话 | 把需求与项目背景交给 AI |
| 2 | 需求澄清 | `/grill-me`：AI 抛问题反问，同时自己给出答案 |
| 3 | 方案对抗性审查 | 新建对话，让另一个 AI 审查原方案 |
| 4 | 规格定稿 | `/to-spec`：把确认下来的内容整理成规格 |
| 5 | 校验规格 | 再开一个对话，检查规格本身对不对 |
| 6 | 拆子任务 | `/to-tickets`：按规格拆解，判断粒度与依赖 |
| 7 | 逐任务开发 | `/tdd`：每个子任务先写测试再实现 |
| 8 | 代码评审 | 新开对话 `/code-review`：一路看仓库规范，一路看规格一致性 |
| 9 | 真机回归 | 按验收标准过一遍 |

### 原作者的四条判断

保留在这里，因为它们是整套方法的立论基础：

> 先写测试，测试就只能照着规格里的要求写；如果先写代码再来补测试，测试往往只是把代码现在的行为抄一遍，代码写错，测试也跟着错。

> 一个需求拆成四个子任务，倘若改了第四个任务的代码影响到了第三个任务的模块，第三个任务的测试会一起跑，哪里改坏了马上能看到。

> 防止开发跑偏，不会因为会话一长，前面的内容被压缩，导致遗忘。写进文件后，每个子任务完成了都会去对照规格。

> 没有规格，`/to-tickets` 和 `/tdd` 这两步只能靠猜。

## 来源二：代码标准

来自 [lengchang-haoyuan/frontend-backend-code-standards-Skill-](https://github.com/lengchang-haoyuan/frontend-backend-code-standards-Skill-)（单次提交 `525d2ee`，2026-08-23）。原仓库 13 个文件、约 1006 行 Markdown 加 333 行 PowerShell，原本绑定某个特定客户端的技能目录与调用语法，另带一个 `agents/openai.yaml` 元数据文件。

它的强项是工程底线写得硬：分层职责、鉴权与服务端授权、事务边界、并发不变量、错误语义、Agent 的工具权限与提示注入，以及两个能真跑的验证脚本。缺的是过程——不澄清、不拆解、不评审、不回归。

### 本仓库怎么处理它

**改写，不复制。** 原仓库没有 LICENSE 文件，公开仓库在无许可证时默认为保留所有权利；规范类文本的思想不受版权保护，逐字复制受保护。因此按同样的技术结论重写了一遍，顺带解决了它本身的几个问题：

| 原始 | 本仓库 | 为什么 |
|---|---|---|
| 绑定特定客户端（私有目录、调用语法、英文 default_prompt） | 去掉路径与语法绑定，`agents/openai.yaml` 不再携带 | 换环境就得改一遍，等于没通用 |
| 7 份 reference，前后端各含示例 | 合并为 5 份：`shared` / `frontend` / `backend-agent` / `mobile` / `examples` | 示例单独成篇，按需才读，减少常驻加载 |
| 产物写 `docs/ai-worklogs/` | 并入 `.ai/operations.md` 与 `.ai/reports/` | 一个项目两套记录目录，必有一套烂掉 |
| 无版本、无变更记录、无许可证 | MIT + CHANGELOG + 语义化版本 | 别人敢用，也敢改 |

技术结论一律保留：优先级次序、八条红线、分层职责、服务端再授权、事务不包远程调用、幂等重试、结构化日志脱敏、工具最小权限、外部内容不得提权、评估集。改的是组织方式与措辞，不是判断。

## 合成后保留了什么

四条过程原则没动：**结论落文件、审查换视角、先定判据再写码、一次一个增量**。

三条标准原则没动：**安全先于正确，正确先于可读**；**不为套用偏好改造无关代码**；**八条红线先确认再执行**。

前四条决定「不做错的事」，后三条决定「不写坏的代码」。合起来才是完整的一套。
