# 模板

两个文件，都在项目根的 `.ai/` 下。用 `python task.py <项目目录>` 自动生成骨架。

## .ai/TASK.md

```markdown
# 给脚本加 --check

一句话：让 `task.py` 能在不修改文件的前提下检查 .ai/ 是否合规。

## 怎么算做完

- [ ] AC-1 目录里没有 .ai/TASK.md 时，`--check` 返回 2 并提示「任务未开始」
- [ ] AC-2 验收标准少于 3 条时报错，返回 1
- [ ] AC-3 报告里缺某条 AC 时报错，并指出缺的是哪条

## 不做什么

- 不做自动修复，只报错
- 不检查代码风格

## 假设

- 用 Python 3.10+，不引入第三方库
```

## .ai/REPORT.md

```markdown
# 完成报告 · 给脚本加 --check

日期：2026-11-08 18:20

## 改了什么

- `scripts/task.py` — 新增 check 模式，四条规则
- `README.md` — 补一段用法

## 验收

| 编号 | 结论 | 证据 |
|---|---|---|
| AC-1 | 通过 | `python task.py /tmp/empty --check` → `任务未开始`，exit 2 |
| AC-2 | 通过 | 删掉一条 AC 后 → `验收标准只有 2 条`，exit 1 |
| AC-3 | 通过 | 删掉报告里 AC-2 行 → `报告缺少 AC-2`，exit 1 |

## 没验的

- 在 Python 3.9 上没跑 —— 因为本机只有 3.14，代码用了 `match` 需要 3.10+

## 下一步

- 可选：加 `--json` 输出，方便别的脚本消费
```

## 写的时候注意

| 别写 | 写成 |
|---|---|
| 「优化了性能」 | 「`--check` 从 1.2s 降到 0.1s，因为不再遍历 node_modules」 |
| 「测试通过」 | 「`pytest -q` → 12 passed in 0.4s」 |
| 「应该没问题」 | 不写。要么跑过，要么进「没验的」 |
| 「临时改了一下」 | 具体改了哪个文件的哪一行、为什么 |

## 验收标准怎么写才算「可判定」

| 不行 | 行 |
|---|---|
| 代码整洁 | 新增函数不超过 30 行，没有重复的解析逻辑 |
| 性能更好 | 同一份输入，耗时从 >1s 降到 <200ms |
| 提示更友好 | 缺文件时报错含文件名和「运行 xxx 生成」的下一步 |
| 功能正常 | 输入 3 组样例，输出与预期逐字相同 |
