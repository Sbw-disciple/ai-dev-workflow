# 模板

两个文件，都在项目根的 `.ai/` 下。用 `python task.py <项目目录>` 生成骨架。

## .ai/TASK.md —— 动工前填

```markdown
# 给脚本加复盘检查

一句话：让 `task.py --check` 能在报告缺复盘时拦住。

## 怎么算做完

- [ ] AC-1 报告缺「复盘」一节时 exit 1，并说明缺什么
- [ ] AC-2 复盘三行里有一行是占位符时 exit 1
- [ ] AC-3 三项齐全时 exit 0

## 分几步

- [ ] 1.1 在 `scripts/task.py` 的 `check()` 里加复盘检查
- [ ] 1.2 给 `templates.md` 的 REPORT 模板补「复盘」一节
- [ ] 1.3 用 /tmp 下的空目录、完整目录、缺复盘目录各跑一次

## 不做什么

- 不检查复盘内容写得好不好，只看有没有填

## 放弃条件

- 如果三天内没跑通，就退回只检查「有没有这节」，不查内容
```

## .ai/REPORT.md —— 收尾时填

```markdown
# 完成报告 · 给脚本加复盘检查

日期：2026-11-08 19:05

## 改了什么

- `scripts/task.py` — 新增复盘检查，三条规则
- `references/templates.md` — REPORT 模板补「复盘」一节

## 验收

| 编号 | 结论 | 证据 |
|---|---|---|
| AC-1 | 通过 | 删掉「复盘」整节 → `复盘缺：判断、下次、rules`，exit 1 |
| AC-2 | 通过 | 三行留空 → `复盘还有 3 处占位符`，exit 1 |
| AC-3 | 通过 | 完整填写 → `全部通过`，exit 0 |

## 复盘

- 哪个判断错了：以为「有大纲就算填了」，实际占位符照样能骗过旧检查
- 下次怎么改：凡是必填章节，一律加占位符检查，不只查章节在不在
- 进 rules.md 吗：是，已加进「写检查脚本」那一节

## 没验的

- Python 3.9 下没跑 —— 因为本机只有 3.14

## 下一步

- 无
```

## 三个容易写坏的地方

| 别写 | 写成 |
|---|---|
| 「优化了性能」 | 「`--check` 从 1.2s 降到 0.1s，因为不再遍历 node_modules」 |
| 「测试通过」 | 「`pytest -q` → 12 passed in 0.4s」 |
| 「应该没问题」 | 不写。要么跑过，要么进「没验的」 |
| 「1.1 优化脚本」 | 「1.1 在 `task.py` 的 `check()` 里加复盘检查」 |
| 「1.2 补测试」 | 「1.2 给 `check()` 加 3 条断言：缺报告、缺 AC、缺复盘」 |

## 步骤拆到什么程度算够

判断标准只有一条：**这一步做完，你能自己判断对不对，不需要再来问一句「这样行吗」。**

- 「改 `task.py`」太粗——改什么、改哪段没说
- 「在 `check()` 的 `problems.append` 之前插入复盘检查」够细——位置和动作都明确
- 「把 6 个 `try/catch` 改成 `attempts` 数组循环」够细——改法本身就说清了
