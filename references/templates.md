# 模板

两个文件，都在项目根的 `.ai/` 下。用 `python task.py <项目目录>` 生成骨架。

## .ai/TASK.md —— 动工前填

```markdown
# 给脚本加复盘检查

一句话目标：报告缺复盘时 `--check` 能拦住，并在 1 行内说清缺什么。

## 范围

**必须有**

- 缺「复盘」整节时报错
- 「复盘」三行里有占位符时报错

**明确不做**

- 不检查复盘写得深不深，只看有没有填
- 不做自动修复

**待定**

- 无

## 怎么算做完

- [ ] AC-1 删掉「复盘」整节 → exit 1，输出里含「判断 / 下次 / rules」
- [ ] AC-2 三行留空 → exit 1，指出第一处占位符
- [ ] AC-3 三项齐全 → exit 0

## 分几步

- [ ] 1.1 `task.py` 的 `check()` 里加复盘检查（完成定义：删掉整节时 exit 1）
- [ ] 1.2 `templates.md` 的 REPORT 模板补「复盘」（完成定义：模板里有这三行）
- [ ] 1.3 三个目录各跑一次（完成定义：退出码 1 / 1 / 0）

## 变更

| 时间 | 改了什么 | 为什么 | 谁同意 |
|---|---|---|---|
| — | — | — | — |

## 放弃条件

- 三天没跑通，就只查「这节在不在」，不查内容
```

## .ai/REPORT.md —— 收尾时填

```markdown
# 完成报告 · 给脚本加复盘检查

日期：2026-11-08 19:05

## 改了什么

- `scripts/task.py` — 新增复盘检查，三条规则
- `references/templates.md` — REPORT 模板补「复盘」一节

## 验收

| 编号 | 结论 | 证据 |
|---|---|---|
| AC-1 | 通过 | 删掉整节 → `「复盘」缺这三样里的：判断、下次、rules`，exit 1 |
| AC-2 | 通过 | 三行留空 → `REPORT.md 还有 3 处占位符没填`，exit 1 |
| AC-3 | 通过 | 完整填写 → `全部通过`，exit 0 |

## 反向检查

- 该做没做的：无（「必须有」两条都对上了）
- 顺手多做的：无（没碰 `rules.md`，虽然想改）

## 复盘

- 哪个判断错了：以为「有大纲就算填了」，占位符照样骗过旧检查
- 下次怎么改：凡是必填章节，一律加占位符检查，不只查章节在不在
- 进 rules.md 吗：是，已加进「写检查脚本」那一节

## 没验的

- Python 3.9 下没跑 —— 因为本机只有 3.14

## 下一步

- 无
```

## 六个容易写坏的地方

| 别写 | 写成 |
|---|---|
| 目标：「优化脚本」 | 目标：`--check` 从 1.2s 降到 0.1s |
| 范围只写「不做什么」 | 三节都写，尤其「必须有」——缺失比越界更难发现 |
| 待定：「再看看」「可能加」 | 要么进「必须有」，要么进「明确不做」，要么写进放弃条件 |
| 步骤：「1.1 优化脚本」 | 「1.1 `task.py` 的 `check()` 里加待定检查」（完成定义：待定非空时 exit 1） |
| 证据：「测试通过」 | 「`pytest -q` → 12 passed in 0.4s」 |
| 反向检查：「都做了」 | 「对着『必须有』两条逐条划：①对上 ②对上；『明确不做』两条：没碰」 |

## 步骤拆到什么程度算够

判断标准只有一条：**这一步做完，你能自己判断对不对，不需要再来问一句「这样行吗」。**

- 「改 `task.py`」太粗——改什么、改哪段没说
- 「在 `check()` 的 `problems.append` 之前插入复盘检查」够细——位置和动作都明确
- 「把 6 个 `try/catch` 改成 `attempts` 数组循环」够细——改法本身就说清了
