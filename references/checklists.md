# 检查清单

按任务范围挑着用，不需要机械复制进报告。打勾的是「做完了才能说完成」，不是「想到了就算过」。

## 一、开始前

- [ ] 已找到项目规则（`AGENTS.md`、贡献指南、ADR）与技术栈
- [ ] 已确认前后端根目录、包管理器、构建与测试命令
- [ ] 已读相关实现、接口、类型、调用方、已有测试
- [ ] 已识别用户未提交的修改，并计划避免覆盖
- [ ] 已明确需求、非目标、兼容与安全边界
- [ ] 已确认验收判据（能跑的命令，或能观察到的现象）
- [ ] 若触碰八条红线中任一条，已准备推荐方案并取得确认

## 二、方案（Gate 1）

- [ ] 改动清单到文件级，每个文件写清改什么、为什么
- [ ] 数据流写清：输入从哪来、经过什么、输出到哪
- [ ] 列了最可能出错的两三处
- [ ] 写了回滚方式，且是一行能执行的命令
- [ ] 做过一次对抗审查，问题逐条标注「已消解」或「接受风险」
- [ ] 八条红线逐条答过「是否触碰」

## 三、实现（阶段 5，每张 ticket）

- [ ] 先写了判据，并确认它当前是红的
- [ ] 改动只覆盖这张 ticket，没有顺手优化
- [ ] 没有跨 ticket 改无关文件
- [ ] 新发现的问题记到「待办」，没有当场做
- [ ] `tickets.md` 里这张已标 `done` 并附一行实际改动

## 四、前端

- [ ] 页面 / feature / 共享组件 / API 层职责清晰，无反向依赖
- [ ] 没有无理由的全局状态、重复组件、重复请求逻辑
- [ ] Props、事件、表单、路由、API 边界类型明确，没有 `any` 掩盖
- [ ] 异步覆盖 loading / empty / error / 取消 / 重试 / 竞态
- [ ] 表单校验、防重复提交、错误定位合理
- [ ] 样式不泄漏；窄屏、长文本、关键状态可用
- [ ] 键盘、焦点、语义标签、可访问名称满足关键交互
- [ ] 无不安全 HTML、开放重定向、前端秘密、敏感日志
- [ ] 监听、订阅、定时器、请求都正确清理
- [ ] 关键行为有测试

## 五、后端

- [ ] Controller 只管传输，Service 管编排，Repository 管持久化
- [ ] DTO、领域对象、数据库实体没有混用或外泄
- [ ] 输入、身份、权限、租户、归属都在服务端验证
- [ ] 状态码、错误码、错误消息、追踪 ID 一致且不泄密
- [ ] 事务里没有长时间远程调用；外部副作用有一致性方案
- [ ] 查询检查了 N+1、索引、稳定排序、有界分页、并发不变量
- [ ] 时间、时区、金额、空值、字符集、序列化语义明确
- [ ] 重试只用于幂等短暂失败，有超时、上限、退避、取消
- [ ] 日志结构化、可关联、已脱敏
- [ ] 单测、集成、API、迁移、并发测试与风险匹配

## 六、Agent

- [ ] 模型、工具、检索、记忆通过窄边界隔离，供应商对象未扩散
- [ ] 提示词、模型参数、工具 schema 集中、版本化、可测试
- [ ] 模型输出和工具参数都按 schema 验证，一律视为不可信
- [ ] 最大回合、超时、取消、令牌/成本预算、停止条件明确
- [ ] 写工具与高影响工具具备最小权限、确认、审计、幂等、恢复方式
- [ ] 外部内容不被当作授权；提示注入和跨租户检索已防护
- [ ] 记忆有隔离、写入条件、过期、删除策略
- [ ] 测试覆盖工具拒绝、解析失败、超时、预算耗尽、注入
- [ ] 可观测性覆盖模型与工具延迟、回合、预算、终止原因

## 七、完成前

- [ ] diff 只含必要改动，没有调试代码和无关格式化
- [ ] 格式、Lint、类型检查、测试、构建、安全检查已跑或标为未运行
- [ ] 本次引入的失败已修；既有失败有可复核证据
- [ ] 文档、接口类型、迁移、测试随行为同步更新
- [ ] `.ai/operations.md` 已追加时间索引记录
- [ ] `.ai/reports/` 下已生成完成报告
- [ ] 最终回复用中文概括结果并给出报告路径
