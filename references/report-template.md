# 完成报告模板

复制到 `.ai/reports/<yyyyMMdd-HHmmss>-<任务简称>.md`，尖括号处填事实，不留空话。

```markdown
# 任务完成报告：<任务名称>

- 完成时间：<yyyy-MM-dd HH:mm:ss +08:00>
- 任务范围：<前端 / 后端 / Agent / 全栈 / 审查>
- 项目根目录：<相对路径>
- 对应规格：<.ai/CONTEXT.md 的小节，或「无规格（小改动）」>

## 需求摘要

<用户目标、必须满足的约束、明确不做什么>

## 修改内容

- <行为变化，以及为什么这样改>

## 文件与架构变化

- `<文件>`：<职责变化>
- 依赖方向：<是否变化，为什么安全>

## 关键设计决定

| 决定 | 原因与取舍 | 用户确认 |
|---|---|---|
| <选择> | <证据> | <不需要 / 已于某时间确认> |

## 兼容性与安全影响

- 公共 API：<无变化 / 已批准的变化>
- 数据与迁移：<无变化 / 已批准的变化>
- 权限、秘密、隐私：<结论>

## 验证结果

| 检查 | 命令 | 结果 | 说明 |
|---|---|---|---|
| 格式 | `<命令>` | 通过 / 失败 / 未运行 | |
| Lint / 静态分析 | `<命令>` | | |
| 类型检查 | `<命令>` | | |
| 单元测试 | `<命令>` | | |
| 集成测试 | `<命令>` | | |
| 构建 | `<命令>` | | |
| 安全检查 | `<命令>` | | |
| 手测路径 | <页面 / 流程> | | |

## 未执行或未通过的检查

- <哪项、为什么、是既有问题还是本次引入、证据是什么、影响范围>

## 剩余风险与后续建议

- <具体风险，或「未发现已知剩余风险」>
```

## 写的时候注意

- 「通过」「失败」「未运行」三个词必须严格区分，不能混着写。
- 不复制大段命令输出，用一行结论加关键数字。
- 未运行的检查是报告里最值钱的一节——它告诉下一个人哪里还没被证明。
